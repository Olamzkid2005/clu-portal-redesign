# The Quad — Chrisland University Portal

[![Design and access audit](https://github.com/Olamzkid2005/clu-portal-redesign/actions/workflows/audit.yml/badge.svg)](https://github.com/Olamzkid2005/clu-portal-redesign/actions/workflows/audit.yml)

A six-role university portal built around the student's day: warm paper, plum, hairline rules and restrained controls. The project is a front-end demo; all accounts and records are fictional.

## Stack

- React 18 and TypeScript
- Vite 6
- Playwright for browser-based design and access audits
- No application backend, database or API keys

## Run locally

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Choose one of the six demo roles on the sign-in screen to open that role's workspace.

## Demo roles

| Role | Landing route | Main workspace |
| --- | --- | --- |
| Student | `#/dashboard` | Timetable, results, payments, accommodation, requests |
| Lecturer | `#/lecturer` | Courses, attendance, gradebook |
| Bursar | `#/bursar` | Ledger, fees, payment reconciliation |
| ICT personnel | `#/ict` | Users, audit trail, systems |
| Vice Chancellor | `#/vc` | Institution overview, approvals |
| Registrar | `#/registrar` | Registry queue and academic records |

Authentication is intentionally client-side. Selecting a role creates a tab-scoped demo session; signing out or closing the tab clears it. There are no passwords, real accounts or persistent sessions. The signed-in design study is available at `#/designs`.

## Build and audit

The audit suite drives the built application in Chromium at **1440px** and **390px**. It checks all **29 routes** — **58 route checks** — for gradients, translucent or glossy surfaces, pill-shaped controls, oversized radii, truncated navigation, horizontal overflow and missing shared design details. It also runs the six-role access flow: clean gate, deep links, session lifetime, sign-out, back/reload behaviour and the signed-in design study.

```bash
npx playwright install --with-deps chromium
npm run build
npm run preview -- --host 127.0.0.1 --port 3000
```

In a second terminal, with the preview server running:

```bash
npm run audit
```

The full audit writes `screenshots/auth/audit.json` and updates the route screenshots. For only the visual route scan:

```bash
npm run audit:routes
```

The audit is a computed-style and geometry check, not a pixel-diff snapshot. It fails the command if any route or access check regresses.

## CI

`.github/workflows/audit.yml` runs on pushes to `main`, pull requests and manual dispatches. It installs dependencies and Chromium, builds the app, starts the preview server, runs the full six-role audit and uploads the report as the `portal-audit` artifact.

## Project layout

```text
src/
  pages/            Student-facing workspaces
  pages/staff/      Staff and executive workspaces
  components/       Shared shell and UI primitives
  quad.css          Shared Quad design system
  designs.css       Design-study styles
scripts/
  auth-gate-audit.mjs   Six-role access and route audit
  route-scan.mjs        Standalone visual route scan
  route-audit-lib.mjs   Route inventory and style scanner
screenshots/        Audit evidence at both viewports
```

## Notes

- The app uses Google Fonts at runtime. The audit does not depend on pixel-perfect font rendering.
- Demo records are local data; no network requests are made for application data.
- The repository includes the audit screenshots as design evidence. They are regenerated by the audit and uploaded from CI.
